# QST WhatsApp Publisher

لوحة عربية RTL لإدارة منشورات فريق QST PRO TEAM وتجهيز حملات مشاركة إلى قروبات واتساب تختارها، مع تأكيد بشري لكل إرسال.

## قرار التكامل مع واتساب

هذا الإصدار **لا يربط حساب واتساب ولا يرسل الرسائل آلياً**. تم اختيار مسار النشر اليدوي الموجّه بدلاً من ربط Baileys/whatsapp-web.js بحسابك الشخصي، لأن هذا الربط غير رسمي وقد يعرّض الحساب لتسجيل الخروج أو التقييد، ولأن سياسات واتساب تشترط أن تكون رسائل الأعمال متوقعة وبموافقة المستلمين وتحذّر من المراسلة غير المصرح بها على نطاق واسع.

واجهة WhatsApp Business Platform الرسمية لا تمنح تطبيقاً عادياً طريقة عامة لسحب كل مجموعات رقمك الشخصي أو قراءة منشورات قناة خاصة بك ثم نسخها إلى مجموعات موجودة. Groups API الرسمية لها شروط أهلية ومخصصة لإنشاء وإدارة مجموعات ضمن واجهة الأعمال، وليست بديلاً عاماً عن مجموعات WhatsApp الشخصية.

لذلك يعمل المشروع حالياً كالتالي:

1. تضيف مجموعاتك يدوياً، مع رابط الدعوة إن توفر.
2. تحفظ النصوص والمرفقات التي تريد نشرها.
3. تنشئ حملة وتحدد المجموعات والمنشور والفاصل المقترح (30 ثانية أو أكثر).
4. تفتح كل مجموعة بنفسك من واتساب، وتنسخ المحتوى وترسله يدوياً.
5. تعود إلى اللوحة وتؤكد الإرسال أو تسجل الفشل. لا يضع النظام علامة نجاح تلقائية.

هذا المسار لا يحتاج إلى جلسة واتساب مخزنة على الخادم ولا يطلب رمز الاقتران أو QR، كما أنه لا يوهمك بأن الإرسال تم قبل تأكيدك.

## الموجود في المشروع

- لوحة تحكم عربية متجاوبة بتصميم Dark Luxury Tech.
- تسجيل دخول مدير مع `bcrypt`، جلسات محفوظة في PostgreSQL، حماية CSRF، وتحديد محاولات تسجيل الدخول.
- إدارة يدوية للمجموعات: إضافة، بحث، تحديد، إلغاء تحديد، تعطيل وحذف.
- إدارة المنشورات: نصوص ومرفقات حتى 3 ملفات لكل منشور ضمن حد 12 MB لكل ملف.
- أنواع ملفات مسموحة: JPG/PNG/WEBP/GIF، MP4/WEBM/MOV، PDF، TXT، DOC/DOCX، ZIP.
- تجهيز حملات متتابعة مع فاصل زمني يفرضه الخادم بين الخطوات بعد تسجيل كل نتيجة؛ الحملة لا ترسل تلقائياً، بل تنظم خطوات النشر اليدوي.
- سجل إرسال؛ تأكيد يدوي للنجاح، تسجيل الفشل، وإظهار وقت العملية.
- إيقاف الحملة واستئنافها وإيقافها نهائياً.
- تنبيهات، تغيير كلمة مرور المدير، وتصدير CSV.
- تخزين المرفقات في PostgreSQL (`BYTEA`)؛ لا تعتمد الملفات على قرص Render المؤقت.

## الميزات غير المتوفرة في هذا المسار

- كود Pairing Code أو ربط رقم واتساب.
- اكتشاف القروبات تلقائياً أو جلب صورها وعدد أعضائها من حسابك.
- التقاط منشورات القنوات تلقائياً.
- الإرسال الآلي أو الإيقاف أثناء الإرسال الشبكي؛ لأن الخادم لا يرسل إلى واتساب أصلاً.
- تشغيل خدمة WhatsApp Web على مدار الساعة.

## المتطلبات

- Node.js 20 أو أحدث.
- PostgreSQL. يمكن استخدام Supabase Free كقاعدة بيانات.
- حساب GitHub لرفع المستودع.
- حساب Render لاستضافة واجهة وخادم Node (الخطة المجانية للتجربة فقط).

## تشغيل محلي

1. انسخ `.env.example` إلى `.env`.
2. ضع بيانات اتصال PostgreSQL في `DATABASE_URL`.
3. أنشئ `SESSION_SECRET` طويلاً وفريداً (32 حرفاً أو أكثر).
4. ضع كلمة مرور المدير في `ADMIN_PASSWORD` بطول 12 حرفاً أو أكثر.
5. نفّذ الأوامر:

```bash
npm install
npm run check
npm test
npm start
```

6. افتح `http://localhost:3000`.
7. في أول تشغيل، ينشئ التطبيق الجداول وحساب المدير تلقائياً إذا لم يكن هناك مدير موجود.

توليد مفتاح جلسة عشوائي:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

## قاعدة البيانات

يمكنك استخدام Supabase:

1. أنشئ مشروعاً جديداً.
2. انسخ PostgreSQL connection string من إعدادات Database، ويفضل استخدام Session Pooler عند وجود مشكلة IPv4.
3. أضف سلسلة الاتصال في `DATABASE_URL` على شكل سر في بيئة الخادم.
4. ينشئ `src/db.js` الجداول تلقائياً في أول تشغيل. لا ترفع بيانات الاتصال إلى GitHub.

مرفقات المنشورات تحفظ داخل قاعدة البيانات. راقب حد 500 MB المعلن للخطة المجانية في Supabase، ولا ترفع ملفات ضخمة أو كثيرة.

## النشر على Render Free

ملف `render.yaml` يجهز Blueprint لخدمة Web Service.

1. ارفع المستودع إلى حساب GitHub.
2. في Render اختر New → Blueprint واربط المستودع.
3. عيّن `DATABASE_URL` و`SESSION_SECRET` و`ADMIN_PASSWORD` كمتغيرات سرية.
4. بعد الإنشاء، افتح رابط `onrender.com` الذي يظهر للخدمة.
5. اختبر `https://YOUR-SERVICE.onrender.com/api/health` ثم افتح الصفحة الرئيسية.

### قيود الخطة المجانية

- Render Free يوقف خدمة الويب بعد 15 دقيقة بلا طلبات واردة، ثم تحتاج عادةً إلى نحو دقيقة للاستيقاظ عند أول طلب.
- نظام ملفات خدمة Render المجانية مؤقت، ولا يوجد قرص دائم مجاني؛ لذلك يعتمد المشروع على PostgreSQL لحفظ البيانات والمرفقات.
- رصيد ساعات التشغيل المجانية محدود وقد تتوقف الخدمة عند استهلاكه أو يعاد تشغيلها. لا يوجد ضمان تشغيل 24/7.
- Supabase Free يتضمن قاعدة بيانات 500 MB ومساحة Supabase Storage مقدارها 1 GB وفق صفحة التسعير الحالية، ويمكن إيقاف المشاريع غير النشطة بعد أسبوع. هذا المشروع يخزّن المرفقات داخل PostgreSQL نفسها لا داخل Supabase Storage؛ لذلك استهلاك المرفقات يُحتسب من حد قاعدة البيانات البالغ 500 MB.
- لا تستخدم قاعدة Render Postgres المجانية كقاعدة رئيسية طويلة الأجل؛ فهي تنتهي بعد 30 يوماً بحسب حدود الخطة الحالية. استخدم قاعدة مستقلة دائمة مثل Supabase Free مع الانتباه إلى سياسة الإيقاف والحدود.

## الاختبارات

- `npm run check` يفحص صياغة الملفات الأساسية.
- `npm test` يشغل اختبارات وحدات الأمان.
- اختبارات الوحدة لا تغني عن اختبار الاتصال بقاعدة PostgreSQL، وفتح الموقع بعد النشر، واختبار سير العمل يدوياً في قروب تجريبي.
- لا توجد اختبارات WhatsApp لأن التكامل غير موجود في هذا الإصدار.
